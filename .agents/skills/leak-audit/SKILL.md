# リーク・因果性監査

禁止事項は [AGENTS.md](../../../AGENTS.md) 第4〜8節を正とする。
監査対象の入力から特徴量・学習・予測までの経路を特定し、source firewall / leak scan と
動的検査を組み合わせる。新規・意味変更したCompetition feature builderは静的検査だけで採用しない。

## 静的・入出力の検査

- 入力の観測日・公開日とPIT join、ローリング・順位化・標準化の時間範囲を確認する。
- 遡及調整済みOHLCVの水準利用、禁止shift・補完、未来targetの流入を追う。
- 予測時のValid target / raw targetへの直接・間接アクセスをfirewallで検査する。
- ソース文字列の一致は候補検出とし、実際に到達する経路と影響を確認する。

## Future-mutation prefix-invariance

1. 同一seed・同一学習条件で、元入力からcutoff以前の特徴量・予測を保存する。
2. cutoff以前を保持し、全入力源のcutoff後を改変する。対象経路に応じて極端値・NaN・0・
   行追加削除やPIT公開日の変更を選び、キャッシュが元結果を再利用しないよう分離する。
3. 改変入力で再計算し、cutoff以前のindex・列・dtype・NaN位置・値を比較する。
   複数の有意味な境界（履歴不足、fold、属性更新等）を選ぶ。
4. 決定論的な処理は厳密一致で検証する。既存契約に数値許容差がある場合はその根拠と
   最大差を記録し、許容差付きの比較を「ビット完全一致」と呼ばない。
   失敗を消す目的で閾値を広げたりskipしたりしない。

学習を含む経路では各cutoffで利用可能なラベル・学習窓も検証する。
固定済みモデルだけのテストで学習時のリークまで検査したと扱わない。

差異が出たら、最初に変化した中間結果と入力の依存関係を調べる。
数値非決定性と未来参照を区別し、原因未解明のまま合格にしない。
合格は試した入力・cutoffにおける証拠であり、全入力に対する数学的証明ではない。

報告には対象ファイル・行、入力源、cutoff、改変方法、比較方法、結果、未検査経路を残す。
