# コードレビュー

共通制約は [AGENTS.md](../../../AGENTS.md)。
差分レビューは変更箇所と影響経路、提出前監査は対象戦略と提出依存を調べる。
レビューのみの依頼ではコードを修正しない。修正も依頼されていれば回帰検証まで進める。

## 重点項目

- **因果性**: AGENTS第4〜8節の禁止事項、直接・間接のデータアクセス、
  対象実装のsource firewallとfuture-mutation検査の証拠。
- **提出契約**: 引数なし `submission.py::predict()`、数値1列のDataFrame、
  `(Date, Code)` MultiIndex、全対象行のcoverage、NaN/Inf非混入。
- **実行可能性**: オフライン、同梱依存、CPUでの動作、採点時間・メモリ。
  30分以内の見込みと実測済みの結果を区別する。
- **数値・再現性**: ゼロ除算、履歴不足、同値分位、joinの重複・順序、seed。
  clipやtie-breakの追加を一律要求せず、仕様と実害に照らす。
- **凍結・研究境界**: 旧snapshotの保全、Train-only比較、研究と提出の予測一致。

確認が必要な挙動だけを小さな再現例や関連テストで検証する。
通常レビューから全戦略バックテストやValid評価を開始しない。

指摘は重要度順に、ファイル・行、発生条件、実害、根拠、最小修正案を示す。
P0: リーク・規約違反・採点不能、P1: 主要機能障害・時間制限超過、
P2: 限定条件の不具合、P3: 任意の保守改善。
確認済みの不具合と未検証の懸念を区別し、指摘がなければその旨と検証範囲を報告する。
