# 挙動を保つリファクタリング

共通制約と検証範囲は [AGENTS.md](../../../AGENTS.md) 第17〜19節。
対象の構造上の問題と比較条件を定め、無関係な変更を混ぜない。

- 同じTrain-only入力・seed・環境で変更前の出力と関連テスト結果を確保する。
  対応する既存artifactを使える場合は再計算を重ねない。
- index、ソート順、NaN処理、特徴量定義、学習窓、パラメータを維持する。
  ベクトル化やdtype変更は計測したボトルネックに適用する。
- 変更前後のindex・列・欠損位置・予測値を比較する。厳密一致と
  `assert_allclose` による許容差付き一致を区別し、閾値は比較前に根拠を定める。
- 演算順序による差がある場合は最大差・順位・分位割当・weight・turnover・Net成績への
  影響をTrain-onlyで確認する。成績が同じだけでは挙動維持と判定しない。
- 影響する経路の [leak-audit](../leak-audit/SKILL.md)、契約・coverage・決定性、
  Train-only smoke / backtestで回帰を確認する。Valid優先の採点を直接実行しない。

特徴量やモデルの意味が変わる場合はリファクタリングとして扱わず、差分を明示する。
凍結済みコードを上書きしない。完了時は構造変更、出力比較、検証結果、
計測した速度・メモリ差を報告する。未計測の改善率は述べない。
