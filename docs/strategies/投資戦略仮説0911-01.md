# 1. 研究目的

前回 `DM-20260910-03` では、通常DTIのdaily adaptationは失敗した。

特に、

```text
DTI RANK + EWMA 0.25
```

でも、

```text
Total Net SR < 0
Long Net SR < 0
Short Net SR < 0
```

となった。

一方、EWMAによってturnover / costは大幅に低下したため、

> DTI representationそのものに弱いGross edgeが存在するが、日次ranking変動と取引コストによってNet alphaとして実現できていない

可能性が残っている。

今回の目的は、

1. DTI scoreをさらに強くslow化する
2. 銘柄固有の通常turnover levelを除去する
3. turnoverへ価格変化の方向情報を付与する
4. turnoverとreturn magnitudeのjoint informationを利用する

ことで、

> **DTI由来signalを取引コスト控除後に正Sharpeへ変換できるか**

をTrain-onlyで検証することである。

---

# 2. 今回の中心仮説

今回検証する仮説は以下。

### H1 — Strong Persistence

DTIのsignal lifespanは1日より長く、scoreを強く平滑化してもGross edgeは残る。

### H2 — Abnormal Turnover

予測力があるのはturnoverの絶対水準ではなく、

> 各銘柄自身の通常状態からどれだけ異常な売買参加が発生したか

である。

### H3 — Signed / Up-Down Turnover

同じ高turnoverでも、

```text
価格上昇を伴う高turnover
価格下落を伴う高turnover
```

は異なる情報を持つ。

### H4 — Return-Conditioned Turnover

turnoverの情報量は、

```text
売買参加強度 × 価格変化の方向・大きさ
```

によって決まる。

# 10. Abnormal Turnover

各銘柄について、通常turnover水準を除去する。

まず、

```math
LTO_{i,t}
=
\log(TO_{i,t}+\epsilon)
```

とする。

baselineは、現在行より前の60 observed trading daysのみを使用する。

```math
BaselineTO_{i,t}
=
Median(
LTO_{i,t-1},
...,
LTO_{i,t-60}
)
```

Abnormal Turnover：

```math
ATO_{i,t}
=
LTO_{i,t}
-
BaselineTO_{i,t}
```

つまり、

```text
ATO > 0
→ 通常よりturnoverが高い

ATO < 0
→ 通常よりturnoverが低い
```

とする。

# 74. Possible Outcomes

## Outcome A — DTI Salvaged

```text
Net SR > 0
positive folds >= 3/4
```

DTI familyにはdaily competitionでも取引可能なalphaがある可能性。

---

## Outcome B — Gross Only

```text
Gross SR > 0
Net SR <= 0
```

10bpsでは取引不可能。

DTI researchを原則終了候補とする。

---

## Outcome C — Representation Success

例えば、

```text
A1/S1/U1/R1
```

がS0/D0を大幅改善するが、まだNet SR <= 0。

次研究候補にはできるが、自動で追加研究しない。

---

## Outcome D — Champion Replacement

```text
Net SR > H0
improvement folds >= 3/4
```

新Champion候補。

---

## Outcome E — Reject

Advanced DTIでも明確なNet alphaを得られない。

DTI familyの探索を終了する。

# 76. 最終原則

今回の研究目的は、

> DTIでTrain Sharpeが最大になるformulaを探索すること

ではない。

目的は、

> **従来DTIに見えていた弱いGross edgeを、低回転化・銘柄固有turnover level除去・return direction / magnitudeとの条件付けによって、10bps控除後にも残る実際のalphaへ変換できるか**

を検証することである。

特に、

```text
Gross alpha
Turnover
Cost
Net alpha
Long leg
Short leg
```

を完全に分離して評価する。

Net Sharpeが負の場合でも、

> 予測力がないのか

と、

> 予測力はあるが取引コストで消えているのか

を必ず区別する。

作業途中で人間への確認を求めず、公式ルール、AGENTS.md、既存実装、本指示から合理的に判断できる範囲は自律的に処理し、Train-only実装・バックテスト・監査・REPORT作成まで完了してください。
