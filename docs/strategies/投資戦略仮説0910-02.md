# 1. 今回の研究目的

今回の目的は、Cakici et al. (2026) の Daily Return Information (DRI) の考え方をStock Competition 2026の1日先残差リターン予測へ適応し、

> **Long側・Short側の両方をDRI scoreだけで構成した場合、現在のChampionより優れたLong/Short portfolioを構築できるか**

をTrain-onlyで検証することである。

現在のChampionは、

```text
Long  = 60日Residual Momentum + EWMA alpha=0.25
Short = Equal-weight Fundamental Deterioration
```

という非対称構造である。

今回はこのLong/Short構造をいったん外し、

```text
High DRI score -> Long
Low DRI score  -> Short
```

という**単一DRI予測モデルによる完全Long/Short ranking**を検証する。

# 22. Long / Short P/L Sign Convention

Long / Short decompositionの符号を曖昧にしない。

Long gross daily P/L：

```math
PL^{long}_t
=
\sum_i
max(w_{i,t},0)
\times
Target_{i,t}
```

Short gross daily P/L：

```math
PL^{short}_t
=
\sum_i
min(w_{i,t},0)
\times
Target_{i,t}
```

Short対象銘柄のTargetが負なら、Short P/Lは正になる。

したがってREPORTで、

```text
Short annual Net = +2%
```

なら、

> Short legそのものが年率+2%収益を生んだ

という意味に統一する。

---

# 23. Long / Short Cost Allocation

weightを、

```math
w^+ = max(w,0)
```

```math
w^- = min(w,0)
```

へ分解する。

Long turnover：

```math
TO^{long}_t
=
\sum_i
|w^+_{i,t}-w^+_{i,t-1}|
```

Short turnover：

```math
TO^{short}_t
=
\sum_i
|w^-_{i,t}-w^-_{i,t-1}|
```

official cost rateを各sideへ配賦する。

必ず、

```math
LongCost + ShortCost = TotalCost
```

および、

```math
LongPL + ShortPL = TotalPL
```

が数値的に一致することをauditする。

---

# 24. Long / Short Sharpe

Long Net Sharpe：

```math
SR^{long}_{net}
=
\sqrt{252}
\frac{
mean(PL^{long}_{net})
}{
std(PL^{long}_{net},ddof=1)
}
```

Short Net Sharpeも同様。

Gross Sharpeも別に計算する。

Long/Short SharpeをTotal Sharpeから推定してはいけない。

各daily leg seriesから直接計算する。

# 56. 最終原則

今回の目的は、

> DRIを使ってTrain Sharpeが最大になるconfigurationを探すこと

ではない。

目的は、

> **Cakici et al.のDaily Return Informationという異なるalpha representationを1日先日本株cross-sectionへ適応したとき、Long側・Short側の両方に独立した予測力が存在し、10bpsの取引コスト後にも現在のChampionを置き換えられるかを検証すること**

である。

特に、

```text
Total
Long
Short
```

を必ず分解する。

総合Sharpeが高くても、

```text
Longだけが強い
Shortだけが強い
```

のであれば、その事実を隠さずREPORTする。

逆にFull DRIが失敗しても、LongまたはShortの片側だけが明確にChampionを上回った場合は、

```text
next research candidate
```

として記録する。

ただし今回そのHybridを実行しない。

作業途中で人間への確認を求めず、公式ルール、AGENTS.md、既存実装、本指示から合理的に判断できる範囲は自律的に処理し、Train-onlyバックテストとREPORT作成まで完了してください。
